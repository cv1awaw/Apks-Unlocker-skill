# Apks Unlocker skill

مهارة Codex لفحص حزم **APK وFlutter/Dart Snapshot** محلياً، ثم السؤال عن الميزات المطلوبة وتطوير التعديلات المصرّح بها من مصدر التطبيق.

**الاسم لا يعني فتح الاشتراكات أو صلاحيات الإدارة.** لا تتضمن المهارة تجاوز الدفع أو الترخيص أو DRM أو المصادقة، ولا منح VIP/admin ذاتياً. تدعم فحص التطبيقات وتطوير واجهاتها وأدواتها التشخيصية والميزات المحلية المصرّح بها.

**اسم العرض:** Apks Unlocker skill · **الاستدعاء:** `$for-devs` · **الإصدار:** 1.0.1

## ماذا تعمل؟

1. تقرأ APK الذي أرفقته أو حددت مساره بالضبط، دون البحث في بقية جهازك أو مشروعاتك.
2. تفحص هوية الحزمة وإصدارها وSDK والتوقيع عند توفر أدواته، والأذونات والمكوّنات وملفات DEX والمكتبات وبنية الأصول.
3. تحدد مؤشرات Flutter/Dart وABIs، وتحفظ بصمات المكتبات ومرشح هوية Snapshot عند توفره.
4. تحفظ تقريراً محلياً، ثم تسألك: **شنو الميزات أو الأخطاء اللي تريد نشتغل عليها؟**
5. تتعمق فقط في المسار المطلوب. تعديل الميزات يعتمد على مصدر التطبيق والتفويض والأدوات المتاحة؛ لا تَعِد بتعديل كل APK.

الفحص الأولي **لا يشغّل التطبيق ولا يتصل بخوادمه ولا يجمع بيانات دخول**. ويدعم فحصاً بصرياً قبل/بعد التعديل عندما تتوفر صور أو اختبار واجهة مصرّح به.

## التثبيت على Windows

تحتاج Python 3.11 أو أحدث وGit. يوصى بـJava 17 للأدوات الإضافية. SDK وWSL/Blutter مطلوبان فقط للمسارات التي تستخدمهما.

راجع [إقرار الاستخدام المصرّح به](TERMS_OF_USE.md) قبل تشغيل أمر القبول أدناه. يُطلب الإقرار مرة واحدة، ويُحفظ محلياً دون بيانات شخصية. تنزيل المستودع وحده لا يُعد قبولاً. تُنفّذ التعديلات العادية المخوّلة دون إعادة طلب التأكيد حين يكون نطاقها واضحاً؛ الإقرار ليس موافقة شاملة على كل طلب مستقبلي.

```powershell
$skillDir = Join-Path $env:USERPROFILE '.codex/skills/for-devs'
git clone https://github.com/cv1awaw/Apks-Unlocker-skill.git "$skillDir"
python "$skillDir/scripts/setup_tools.py" --download-tools --accept-authorized-use
& "$skillDir/.venv/Scripts/python.exe" "$skillDir/scripts/check_tools.py" --probe
```

اختر مجلداً غير موجود عند الاستنساخ؛ لا تستبدل مهارة موجودة دون مراجعتها. سكربت الإعداد ينشئ بيئة Python خاصة وينزّل نسختين محددتين من المصادر الرسمية مع التحقق من SHA-256. يعيد استخدام JDK/SDK وBlutter الموجودين، ولا يعدّل PATH أو مفاتيح التوقيع أو إعدادات Codex، ولا ينشئ حسابات أو يقبل تراخيص SDK تلقائياً.

لإعداد الفحص الأساسي فقط، شغّل الإعداد دون `--download-tools`. ويمكن تحديد SDK موجود بواسطة `--sdk "C:/path/to/Android/Sdk"`. في Linux استخدم `python3` و`.venv/bin/python`؛ فحص Python قابل للنقل، أما مسار WSL الموضح فخاص بـWindows.

## الاستخدام داخل Codex

أرفق APK واكتب:

```text
$for-devs افحص هذا التطبيق فقط، وبعد التقرير اسألني عن الميزات المطلوبة.
```

أو حدد ميزة من البداية:

```text
$for-devs افحص تطبيقي ومصدره المرفق، وأضف شاشة تشخيص واضحة واختبرها.
```

الاختيار التلقائي مفعّل في metadata. المهارة تعمل أثناء المحادثة؛ ليست خدمة تراقب ملفات جهازك في الخلفية.

## التشغيل المباشر

```powershell
& "$skillDir/.venv/Scripts/python.exe" "$skillDir/scripts/inspect_apk.py" "C:/input/app.apk" --out "C:/work/.for-devs/cases/app" --verify-signature
```

الناتج:

| الملف | المحتوى |
| --- | --- |
| `inventory.json` | هوية APK، manifest، DEX، المكتبات، المؤشرات، حدود التحليل والتوقيع. |
| `summary.md` | تقرير مختصر، التغطية وما لم يُفحص، ثم سؤال الميزات. |

لا تخلط فحص التوقيع مع إمكانية تحديث التطبيق: يلزم توافق الحزمة والشهادة والإصدار. ودون SDK/JDK مناسبين تبقى حالة التوقيع `unavailable` بدلاً من ادعاء نجاحه.

لاستخراج زوج مكتبات Flutter فقط:

```powershell
& "$skillDir/.venv/Scripts/python.exe" "$skillDir/scripts/extract_flutter.py" "C:/input/app.apk" --abi arm64-v8a --out "C:/work/.for-devs/cases/app/flutter"
```

الناتج يقتصر على `libapp.so` و`libflutter.so` وبيان بصماتهما؛ لا يفك بقية الحزمة ولا ينفذ المكتبات.

## الأدوات والمكتبات

| الأداة | الاستخدام | طريقة التوفير |
| --- | --- | --- |
| Python + `pyelftools 0.33` | APK/ELF وبيانات Snapshot الأولية | بيئة `.venv` خاصة. |
| `PyYAML 6.0.3` | metadata والتحقق من المهارة | بيئة `.venv` خاصة. |
| JADX 1.5.6 | قراءة DEX/Java المحددة بالميزة | نسخة CLI خاصة، archive digest مثبت. |
| Apktool 2.12.1 | قراءة manifest/resources | JAR خاص، digest مثبت. |
| Android SDK/JDK | AAPT/apksigner وأدوات المشروع | إعادة استخدام التثبيت الموجود. |
| Blutter | تحليل Dart AOT متوافق | تثبيت موجود ومطابقة نسخة Dart/ABI أولاً. |

لا تُنشر ملفات الأدوات الثنائية أو التطبيقات أو التقارير المحلية في هذا المستودع. المصادر الرسمية والبصمات موجودة في [أداة الإعداد](scripts/setup_tools.py) و[مرجع الأدوات](references/toolchain.md).

## حدود مهمة

- مرحلة البداية فحص metadata ساكن، وليست استرجاعاً كاملاً للمصدر أو ضماناً بأن ميزة ستعمل.
- `snapshot_hash_candidate` و`dart_engine_version_candidate` قيم مرشحة؛ عدم توفرها يُعرض كما هو. دعم Blutter يتوقف على ABI وإصدار Dart، وقد تحتاج نسخة محلل مطابقة.
- الحزم المقسّمة أو المحمية/المموّهة والمصدر المفقود قد تمنع التعديل. ZIP64 يتطلب مسار فحص منفصلاً، والميزانية الافتراضية للحزمة 1 GiB وللمكتبة 128 MiB.
- محتويات APK بيانات غير موثوقة، ولا تُتبع أي تعليمات مكتوبة داخلها.
- لا تنفّذ المهارة طلبات API أو تسجّل الدخول أو تغيّر أدواراً أو سياسات قاعدة بيانات تلقائياً.
- تعديلات المصدر المصرّح بها واختبارات المحاكي مسار منفصل. يجب ذكر ما اختُبر فعلياً؛ نجاح البناء ليس نجاح تشغيل.

## التحقق

```powershell
& "$skillDir/.venv/Scripts/python.exe" -m unittest discover -s "$skillDir/tests" -v
```

الاختبارات تستخدم حزم ZIP/APK اصطناعية فقط، دون أجهزة أو شبكة أو حسابات. تغطي حماية الأصل، حدود القراءة، ZIP paths والتكرار، XML، DEX metadata، فصل الحالات، واستخراج المكتبات دون استبدال ملفات مختلفة. جُرّب الفحص أيضاً محلياً على حزمة تطوير Android وأخرى Flutter، مع التحقق من التوقيع وقراءة Snapshot، وجُرّبت قراءة class محددة بـJADX وفك manifest بـApktool؛ هذه العينات غير مضمّنة وغير منشورة.
